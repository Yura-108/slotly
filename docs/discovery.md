# Discovery: платформа онлайн-записи к специалистам

> Статус: завершён. Начат 2026-11-04, закрыт 2026-11-06.
> Рабочее название продукта: **Slotly** (можно поменять).

## 1. Проблема

Частные специалисты (репетиторы, мастера, консультанты, психологи, тренеры) часто ведут запись клиентов вручную — в мессенджерах, заметках, бумажных ежедневниках.

Последствия:

- **Для специалиста:** время на переписку «а в четверг можно?», двойные записи на одно время, неявки клиентов, нет единой картины загрузки.
- **Для клиента:** нельзя самому увидеть свободное время и записаться в любой момент; нужно ждать ответа.

## 2. Целевая аудитория

Основной сегмент — **частные специалисты, работающие индивидуально** (один специалист = одно расписание), и их клиенты.

Вне фокуса: салоны и клиники с несколькими сотрудниками и администратором (другая модель прав и процессов, см. «Границы»).

## 3. Пользователи и их потребности

| Роль       | Кто это                                   | Ключевые потребности                                                                                                                        |
| ---------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Специалист | Владелец расписания, предоставляет услуги | Один раз описать услуги и рабочее время; получать брони без переписки; не допускать пересечений; управлять (подтверждать/отменять) записями |
| Клиент     | Человек, записывающийся на услугу         | Быстро увидеть свободное время; записаться в пару кликов; видеть свои записи; отменить при необходимости                                    |

Один аккаунт может быть и специалистом, и клиентом (решение в разделе 8).

## 4. Аналоги

| Продукт                  | Модель                                    | Что берём как идею                                                 | Чем отличаемся                                     |
| ------------------------ | ----------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| Calendly                 | Платформа для индивидуальных специалистов | Правила доступности → вычисляемые слоты; публичная страница записи | Проще: без интеграций с внешними календарями в MVP |
| Cal.com                  | Open-source аналог Calendly (Next.js)     | Можно изучать реальный код и модель данных                         | Учебный масштаб                                    |
| YCLIENTS, Fresha, Booksy | Решения для салонов (много сотрудников)   | Подтверждение записей, статусы, напоминания                        | Не поддерживаем организации и сотрудников          |

Ключевой вывод из аналогов: **слоты не хранятся заранее, а вычисляются** из правил расписания специалиста за вычетом уже занятого времени.

## 5. Ключевые пользовательские сценарии (черновик)

1. Специалист регистрируется и получает публичную страницу записи.
2. Специалист описывает услуги (название, длительность) и рабочее расписание.
3. Клиент открывает страницу специалиста, выбирает услугу и видит свободные слоты.
4. Клиент (с аккаунтом) бронирует слот.
5. Специалист подтверждает или отклоняет бронь.
6. Клиент или специалист отменяет запись.
7. Специалист и клиент видят списки своих записей.

## 6. Границы продукта

Принятые решения по масштабу:

| Вопрос          | Решение                                                             | Почему                                                                        |
| --------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Модель продукта | Платформа: любой специалист регистрируется и получает свою страницу | Даёт роли и авторизацию на уровне владения ресурсом без сложности организаций |
| Запись клиента  | Только с аккаунтом                                                  | Одна система аутентификации для обеих ролей; гостевую запись — позже          |
| Оплата          | Вне MVP (оплата на месте)                                           | Платежи сильно увеличивают объём; рассматриваем как расширение                |

Явно **не входит** в продукт на старте:

- организации, сотрудники, администратор салона;
- онлайн-оплата;
- синхронизация с Google/Outlook Calendar;
- мобильные приложения;
- маркетплейс/поиск специалистов по каталогу.

## 7. Инженерно интересные места (почему эта идея)

- **Конкурентность:** два клиента одновременно бронируют один слот → транзакции, ограничения БД.
- **Работа со временем:** часовые пояса специалиста и клиента, интервалы, переход на летнее время.
- **Машина состояний** брони: pending → confirmed / rejected / cancelled.
- **Авторизация по владению ресурсом:** клиент видит только свои брони, специалист — только брони к себе.
- **Фоновые задачи** (позже): напоминания о записи.

## 8. Решения по открытым вопросам (2026-11-06)

| Вопрос                         | Решение                                                                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Подтверждение брони            | Настройка специалиста: автоподтверждение или ручное                                                                          |
| Занимает ли pending-бронь слот | Да. Чтобы забытая заявка не держала слот вечно, у pending есть срок истечения (см. требования)                               |
| Правила отмены                 | Специалист — в любой момент; клиент — не позже чем за N часов до начала (N задаёт специалист, по умолчанию 24)               |
| Ограничения бронирования       | Минимальное время до записи и горизонт бронирования — настройки специалиста. Буферы — после MVP                              |
| Исключения из расписания       | Целые выходные дни/отпуск — MVP; частичные изменения дня — после MVP                                                         |
| Часовые пояса                  | Моменты времени в UTC; правила расписания — в локальном времени специалиста + IANA-пояс; клиенту показываем в поясе браузера |
| Уведомления                    | Email о ключевых событиях брони — MVP; напоминания — после MVP                                                               |
| Роли                           | Один аккаунт может быть и клиентом, и специалистом; профиль специалиста включается дополнительно                             |
