# ADR-006: Слои и модули backend

- **Статус:** Принято
- **Дата:** 2026-11-09

## Контекст

Backend — модульный монолит на NestJS ([ADR-001](001-system-topology.md)). Самая сложная логика — расчёт слотов (часовые пояса, переход на летнее время, выходные) и машина состояний брони; её нужно тестировать быстро и изолированно. Корректность при конкурентности обеспечивается БД ([ADR-003](003-double-booking-protection.md)), поэтому доступ к данным должен проверяться на настоящем PostgreSQL, а не на моках.

## Варианты

### Классический NestJS: controller → service (с ORM внутри)

- ➕ Минимум кода.
- ➖ Бизнес-правила перемешаны с SQL; тест правила требует БД.

### Clean / hexagonal архитектура в полном объёме

- ➕ Строгая изоляция домена, заменяемая инфраструктура.
- ➖ Интерфейсы и адаптеры на каждый репозиторий ради замены ORM, которой не будет; много кода без пользы на нашем масштабе.

### Прагматичные слои

controller → service → чистый domain + конкретный repository; domain-слой — только там, где есть правила.

- ➕ Сложная логика изолирована и покрывается быстрыми unit-тестами без моков.
- ➕ Доступ к данным проверяется интеграционными тестами на настоящей БД.
- ➖ Требует дисциплины: границу «что в domain, что в service» нужно держать на ревью.

## Решение

**Прагматичные слои** и модули с явным владением таблицами — подробно в [backend.md](../architecture/backend.md). Ключевые правила:

- Таблицу пишет и читает только модуль-владелец; межмодульное взаимодействие — через экспортированные сервисы.
- Граф зависимостей модулей ацикличен; `forwardRef` запрещён.
- Слоты и создание брони — use case'ы модуля `bookings`, который зависит от `scheduling` (не наоборот).
- `notifications` не зависит от других модулей: payload outbox содержит всё нужное для письма.
- Транзакции открываются в service, `tx` передаётся явно.
- Доменные функции получают текущее время параметром.
- Фоновые задачи — в том же процессе, с `FOR UPDATE SKIP LOCKED`.

## Последствия

- Нужна автоматическая проверка границ модулей в линтере (этап 4) — особенно важна при работе с AI-агентами, которые легко добавят «быстрый» импорт чужого репозитория.
- Явная передача `tx` делает сигнатуры репозиториев чуть длиннее, но транзакционные границы видны в коде.
- При росте фоновой нагрузки обработчик выносится в отдельный процесс без изменения кода модулей (меняется только точка входа).
