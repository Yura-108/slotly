# ADR-017: Непрерывная интеграция и защита main

- **Статус:** Принято
- **Дата:** 2026-11-13

## Контекст

На каждом PR проверялся только заголовок. Линтер, типы, тесты, аудит, поиск секретов выполнялись на машине разработчика — по дисциплине; любой мог слить PR с красными проверками или запушить в `main`. Репозиторий стал публичным: защита веток доступна бесплатно, но PR может открыть любой, в том числе из форка.

## Решение

### Workflow `ci.yml`

Запускается на `pull_request` и на push в `main`. Три задачи параллельно — каждая отдельная обязательная проверка:

| Задача     | Что проверяет                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| `checks`   | `pnpm lint` (с границами модулей), `typecheck`, `format:check`, `audit:prod`, `secrets:check`, дрейф контракта API |
| `test`     | `pnpm test`: юнит и интеграционные тесты, PostgreSQL и Mailpit через testcontainers (Docker есть на раннере)       |
| `gitleaks` | вся история git (`fetch-depth: 0`): secretlint видит только текущие файлы, а удалённый секрет остаётся в истории   |

- **Дрейф контракта.** CI перегенерирует `openapi.json` и `schema.d.ts` и падает на `git diff --exit-code`: изменённый DTO без перегенерации дал бы web устаревшие типы. `api:types` сам форматирует результат Prettier, поэтому генерация воспроизводима байт в байт, а `schema.d.ts` больше не в `.prettierignore`.
- **Канарейка gitleaks.** Перед сканированием истории gitleaks обязан найти секрет, подложенный во временный репозиторий; токен собирается во время выполнения, его литерала в репозитории нет. Зелёная проверка значит «секретов нет», а не «сканер ничего не находит».
- **Ложные срабатывания gitleaks** подавляются в `.gitleaksignore` отпечатком находки (коммит, файл, правило, строка) с причиной, а не отключением правила. Первый прогон нашёл тестовый пароль хешера из среза 5.1.
- **Первый прогон** нашёл и зависимость от локального окружения: `next typegen` загружает `next.config.ts`, а тот требует `API_INTERNAL_URL` — локально он приходил из `.env`.
- Браузерные e2e и мутационное тестирование — отдельный срез 8.2.

### Защита самого CI (security.md, A08)

- `permissions: contents: read`: токен не может писать в репозиторий.
- Событие `pull_request`, не `pull_request_target`: запуск для PR из форка не получает ни секретов, ни прав на запись. Запуск для внешних участников требует одобрения владельца (настройка репозитория).
- Сторонние actions закреплены по **SHA коммита**, версия — комментарием. Тег — изменяемый указатель: в марте 2025 теги `tj-actions/changed-files` передвинули на вредоносный коммит, и тысячи CI напечатали свои секреты в логи. SHA вычисляется из содержимого и передвинут быть не может. Цена — обновлять SHA при новой версии (делает Dependabot, экосистема `github-actions`) и хуже читаемость.
- gitleaks скачивается из релиза и сверяется по sha256 из `checksums.txt` — SHA action не закрепляет то, что action скачивает сам.
- `persist-credentials: false` — токен не остаётся в `.git/config` для следующих шагов.
- `concurrency` отменяет устаревший прогон PR; `timeout-minutes` у каждой задачи.

### Ruleset ветки `main`

Только через PR; обязательны `checks`, `test`, `gitleaks` и проверка заголовка (`pr-title.yml`); запрещены force push и удаление ветки. Squash merge — единственный способ слияния (настройка репозитория, ADR-010).

### Настройки репозитория (владелец)

Dependabot alerts и security updates (без них `dependabot.yml` даёт только плановые обновления — в срезе 7.3 это было упущено), private vulnerability reporting, одобрение запуска CI для всех внешних участников; secret scanning с push protection.

## Последствия

- Красная проверка блокирует слияние — правила CLAUDE.md «задача не завершена, пока не пройдены линтер, типы и тесты» теперь проверяет машина.
- PR от Dependabot проверяются так же; их можно сливать по зелёному CI.
- Публичный репозиторий: бесплатные минуты Actions, защита веток, secret scanning. История git публична — она проверена (ADR-015) и проверяется gitleaks на каждом прогоне.
