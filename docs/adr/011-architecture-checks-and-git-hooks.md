# ADR-011: Автоматическая проверка архитектурных границ и pre-commit

- **Статус:** Принято
- **Дата:** 2026-11-09
- **Уточняет:** [ADR-010](010-development-environment.md) — инструмент проверки границ модулей (там предполагались плагины ESLint).

## Контекст

Правила [ADR-006](006-backend-layers-and-modules.md) и [ADR-009](009-frontend-structure.md) держатся на дисциплине: таблицу читает только модуль-владелец, граф модулей ацикличен, контроллер не обращается к репозиторию, домен не знает про NestJS и Drizzle, фичи web не импортируют друг друга. Код пишется в том числе AI-агентами, которые легко добавляют «быстрый» импорт чужого репозитория. Нарушение должно останавливать проверку, а не ждать ревью.

Отдельно — pre-commit: ADR-010 разрешает в нём только быстрые проверки изменённых файлов.

## Варианты

### Границы: eslint-plugin-boundaries

- ➕ Ошибка видна сразу в редакторе.
- ➖ Не проверяет циклы в графе (нужен ещё `import/no-cycle`, медленный на больших проектах).
- ➖ Правила описываются через «типы элементов»; разрешённый граф модулей выражается громоздко.
- ➖ Два ESLint (9 в web, 10 в api) — две совместимости плагина.

### Границы: dependency-cruiser

- ➕ Анализирует весь граф импортов: циклы, запреты по путям, тип зависимости (dev, type-only).
- ➕ Конфигурация — JS: граф модулей задаётся объектом, который один к одному повторяет [backend.md §2](../architecture/backend.md).
- ➕ Учитывает type-only импорты: `import type` из чужого модуля — тоже связь.
- ➖ Не в редакторе: ошибка видна при `pnpm lint`.

### pre-commit: husky + lint-staged / lefthook / simple-git-hooks

- husky 9 — без скриптов установки (хук ставится скриптом `prepare` самого проекта), де-факто стандарт.
- lefthook — бинарник со скриптом установки (нужно `allowBuilds`), свой формат конфигурации.
- simple-git-hooks — минималистичен, но для запуска проверок только по изменённым файлам всё равно нужен lint-staged.

## Решение

- **dependency-cruiser** в каждом приложении (`apps/*/.dependency-cruiser.cjs`), запускается в составе `pnpm lint`.
  - api: ацикличность; граф модулей из backend.md (каждое новое ребро — правка конфигурации и документа); чужой модуль — только через `*.module.ts` и `*.service.ts`; schema-файлы ссылаются друг на друга только ради внешних ключей; домен без NestJS, Drizzle, `pg` и без импорта других слоёв; контроллеры модулей без доступа к данным; `infrastructure` и `shared` не зависят от модулей; production-код не импортирует тестовый код и devDependencies.
  - web: ацикличность; фичи изолированы; `shared` не зависит от фич и маршрутов; нет драйверов БД и импорта кода других пакетов.
- **ESLint** дополняет то, что не видно в графе: в домене api запрещены `Date.now()` и `new Date()` без аргументов (время — параметр).
- **pre-commit: husky + lint-staged.** Prettier и ESLint только для staged-файлов, последовательно; у каждого приложения своя конфигурация lint-staged (ESLint запускается из каталога пакета со своей версией и конфигурацией). Граф зависимостей, типы и тесты — в `pnpm lint/typecheck/test` и CI.
- **Заголовок PR** проверяется workflow GitHub Actions без сторонних actions: заголовок передаётся через `env`, а не подставляется в скрипт (защита от инъекции команд).

## Последствия

- Нарушение границ ломает `pnpm lint` и, с этапа 8, CI. Каждое правило проверено временным файлом-нарушителем.
- Новый модуль api нельзя использовать, пока он не объявлен в графе конфигурации, — изменение архитектуры становится явной правкой.
- Ошибки границ не подсвечиваются в редакторе; это осознанная цена.
- `git commit --no-verify` обходит хук; страховка — проверки в CI.
