# ADR-008: Логирование и конфигурация

- **Статус:** Принято
- **Дата:** 2026-11-09

## Контекст

В production нужно быстро находить конкретный запрос пользователя и понимать, что с ним произошло, не раскрывая в логах секретов и персональных данных (requirements §6.1, §6.3). Приложение работает в нескольких окружениях (локально, CI, production); ошибки конфигурации должны обнаруживаться при старте.

Документация сверена 2026-11-09 (Context7: NestJS docs — `ConsoleLogger` с JSON-режимом, `@nestjs/config`; nestjs-pino). Обнаружен `@nestjs/observe` — SDK, связанный с платформой наблюдаемости NestJS; условия использования не изучались.

## Варианты

### Логирование

- **Встроенный `ConsoleLogger` (JSON-режим):** без зависимостей; строку на запрос, корреляцию и маскировку нужно писать самим.
- **nestjs-pino:** строка на запрос, request-контекст через AsyncLocalStorage, встроенная маскировка `redact`, высокая производительность; ещё одна зависимость.
- **`@nestjs/observe`:** привязан к платформе мониторинга — рассматривается на этапе 9.

### Конфигурация

- **`process.env` напрямую по коду:** ошибки проявляются в момент использования, нет типов.
- **`@nestjs/config` + проверка схемой при старте + типизированный доступ.**

## Решение

- **nestjs-pino**: JSON в stdout, `requestId` в каждой строке, `redact` для секретов, тела запросов не логируются, в логах `userId` вместо персональных данных.
- **Конфигурация из переменных окружения**, проверка **Zod-схемой при старте**, доступ через типизированный `AppConfig`; `process.env` вне модуля конфигурации запрещён линтером.
- **Токены из писем — во фрагменте URL** (`#token=`), удаляются из адресной строки сразу после чтения; `Referrer-Policy: no-referrer`.

Подробности — [observability-and-config.md](../architecture/observability-and-config.md).

## Последствия

- По `requestId` из сообщения об ошибке находится весь путь запроса.
- Добавление нового поля в логи требует проверить, не персональное ли оно и не секрет ли.
- Нет файлов логов на диске — хостинг должен собирать stdout (критерий выбора на этапе 9).
- Отслеживание ошибок (Sentry или аналог) и `@nestjs/observe` — решение этапа 9.
- Страницы подтверждения email и сброса пароля на web читают токен из `location.hash` и отправляют его в API методом POST.
