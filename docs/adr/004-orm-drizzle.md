# ADR-004: ORM — Drizzle

- **Статус:** Принято (подтверждается прототипом на этапе 4)
- **Дата:** 2026-11-09

## Контекст

Backend (NestJS, [ADR-001](001-system-topology.md)) работает с PostgreSQL. Ядро продукта опирается на специфичные возможности PostgreSQL ([ADR-003](003-double-booking-protection.md)): exclusion constraint с `tstzrange`, обновление по пересечению интервалов внутри транзакции, обработка кода ошибки `23P01`. Обычный CRUD (пользователи, услуги, расписание) составляет большую часть запросов.

Главный критерий — насколько естественно инструмент позволяет писать SQL там, где это нужно, не теряя типизации в остальном коде. Дополнительный — учебная цель: понимать, какой SQL уходит в БД.

Документация сверена 2026-11-09 (Context7: документация Prisma ORM v7 и Drizzle ORM).

## Варианты

### Prisma 7

- ➕ Зрелая, самая распространённая, отличная типизация и DX.
- ➕ Для нестандартного SQL есть TypedSQL (типизированные `.sql`-файлы).
- ➖ Exclusion constraint не описывается в схеме — только ручной правкой миграции (`migrate dev --create-only`).
- ➖ Ядро брони окажется на `$queryRaw`/TypedSQL — отдельно от основного API запросов.
- ➖ v7 требует driver adapter, генерирует клиент в проект, документация ориентирована на ESM — возможное трение с CommonJS-сборкой NestJS.

### Drizzle

- ➕ SQL-first: builder близок к SQL, `sql`-шаблон с параметризацией встраивается в обычные запросы.
- ➕ Схема на TypeScript; миграции — обычные SQL-файлы, которые читаются на ревью.
- ➕ Нестандартный DDL — через пустую миграцию `drizzle-kit generate --custom`.
- ➕ Транзакции с явным уровнем изоляции.
- ➖ Версия до 1.0, идёт переработка API реляционных запросов — возможны breaking changes.
- ➖ Меньше экосистема и готовых интеграций с NestJS.

### TypeORM

- ➖ Слабее типизация запросов, известные проблемы автогенерации миграций; выигрыша для SQL-ядра нет.

## Решение

**Drizzle ORM** с **drizzle-kit** для миграций.

## Последствия

- Версии `drizzle-orm` и `drizzle-kit` закрепляются точно; обновление — отдельной задачей с чтением changelog.
- Миграции — SQL-файлы в репозитории, проходят code review как код. Exclusion constraint и расширение `btree_gist` — в custom-миграции.
- Ошибки драйвера `pg` (в том числе `23P01`, `23505`) транслируются в доменные ошибки в одном месте инфраструктурного слоя.
- Интеграция с NestJS — собственный провайдер БД через DI (без сторонних обёрток, пока не появится конкретная причина).
- **Прототип на этапе 4** проверяет: custom-миграцию с exclusion constraint, перехват `23P01`, интеграционный тест одновременного бронирования на настоящем PostgreSQL. Если прототип выявит блокирующую проблему — пересматриваем решение новым ADR.
