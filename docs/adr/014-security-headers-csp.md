# ADR-014: Заголовки безопасности и CSP с nonce

- **Статус:** Принято
- **Дата:** 2026-11-12

## Контекст

Ни web, ни API не отправляли заголовков безопасности ([security.md](../architecture/security.md), A02). Главная защита от XSS — React экранирует вывод, но второго рубежа не было: если разметка злоумышленника попадёт в страницу (забытое экранирование, уязвимая зависимость), браузер выполнит её скрипт от имени пользователя. `HttpOnly` не даёт украсть cookie, но скрипт может отправлять запросы с ней: отменять брони, менять профиль.

Content-Security-Policy разрешает браузеру выполнять только скрипты, одобренные сервером. Сложность — App Router вставляет в HTML **встроенные** `<script>` (данные для гидратации, загрузчик), и их нужно отличить от встроенных скриптов злоумышленника.

## Варианты

### A. `script-src 'self' 'unsafe-inline'`, статический заголовок

Просто, страницы остаются статическими. Но встроенный скрипт злоумышленника тоже выполнится — от XSS такая CSP почти не защищает.

### B. Хеши и SRI (`experimental.sri`)

Хеши файлов скриптов на этапе сборки, статическая генерация сохраняется. Экспериментально; данные для гидратации всё равно встроены и хешами не покрыты — снова нужен `'unsafe-inline'`. Next.js готовит `externalBrowserRuntime`, но и он, по документации, пока недостаточен.

### C. Nonce на каждый запрос + `'strict-dynamic'`

`proxy.ts` генерирует случайный nonce на каждый ответ и кладёт CSP в заголовки запроса и ответа. Next.js при рендеринге читает nonce из заголовка и сам ставит его на свои скрипты; `'strict-dynamic'` разрешает им подгружать чанки. Встроенный скрипт, обработчик `onerror="…"` или скрипт с чужого хоста без nonce блокируются. Цена: страница должна рендериться на каждый запрос (в статическом HTML nonce не вставить), HTML не кэшируется на CDN.

## Решение

**Вариант C.** Почти все страницы и так динамические (сессия, данные API); статическими были бы только `/`, `/login`, `/register`, `/forgot-password` — для них лишний серверный рендер стоит миллисекунды. CDN-кэш HTML в MVP не нужен.

Nonce обязан быть новым на каждый ответ: он виден в HTML любой страницы, и постоянный nonce злоумышленник прочитал бы у себя и вписал в свою разметку — это было бы равно `'unsafe-inline'`.

Политика страниц (`apps/web/src/shared/config/security-headers.ts`, юнит-тесты):

- `default-src 'self'`; `script-src 'self' 'nonce-…' 'strict-dynamic'`; `style-src 'self' 'nonce-…'`; `img-src 'self' data: blob:`; `font-src`, `connect-src 'self'`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self'`; `frame-ancestors 'none'` (вместо `X-Frame-Options`).
- Только в разработке: `'unsafe-eval'` (React восстанавливает стеки ошибок сервера) и `style-src 'self' 'unsafe-inline'` (оверлей Next.js вставляет стили без nonce; при наличии nonce браузер `'unsafe-inline'` игнорирует, поэтому nonce из `style-src` в dev убран).
- Статические заголовки из `next.config.ts`: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (камера, микрофон, геолокация, оплата — запрещены), HSTS на год — только в production-сборке (по HTTP браузер его игнорирует, а в разработке он закрепил бы HTTPS за localhost). `/api/*` эти заголовки не получает — у API свои.
- Корневой layout вызывает `await connection()`: без него статические страницы собираются без nonce, и CSP блокирует все их скрипты (проверено мутацией).
- Zod 4 в браузере проверяет, доступен ли `new Function`, и CSP сообщает о нарушении, хотя ошибка перехвачена. Клиентский код импортирует `z` из `@/shared/lib/zod`, где включён `jitless`; прямой импорт `zod` в `src/` запрещён ESLint.

API отдаёт только JSON, поэтому вместо `helmet` — middleware на пять заголовков (`apps/api/src/infrastructure/http/security-headers.ts`) до всех маршрутов: `Cache-Control: no-store` (персональные данные не оседают в кэшах), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`.

## Последствия

- Встроенный скрипт и обработчик событий в HTML от сервера не выполняются — проверено браузерным тестом, который подменяет ответ страницы, добавляя такую разметку.
- Любое нарушение CSP в браузерных e2e роняет тест (фикстура собирает `securitypolicyviolation` со всех контекстов). Новая библиотека со встроенными стилями, `eval` или скриптом с чужого хоста будет замечена в тестах, а не пользователями.
- Внешние скрипты, шрифты и изображения (аналитика, CDN шрифтов, аватары) требуют осознанной правки политики.
- Все страницы рендерятся на сервере на каждый запрос. Если понадобится CDN-кэш HTML — пересмотреть (вариант B, когда SRI и `externalBrowserRuntime` станут стабильными).
- Отчёты о нарушениях из production (`report-to`) не собираются — вместе с мониторингом на этапе 9.
